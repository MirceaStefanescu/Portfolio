# Security policy

These projects are portfolio demonstrations, not supported production services.
Security fixes target the current main branch; historical tags are not maintained.

## Reporting a vulnerability

Use [Report a vulnerability](https://github.com/MirceaStefanescu/Portfolio/security/advisories/new)
to send details privately when private vulnerability reporting is available.
Do not post credentials, exploit details, or private data in a public issue.
If the private reporting form is unavailable, open an issue asking for a private
contact method without including vulnerability details.

Include the affected project and version, reproduction steps, impact, and any
proposed fix. Each project's SECURITY.md documents its additional boundaries.

## Development

Use synthetic data and the documented local demo configuration. Keep secrets and
local environments out of commits. Pull requests must pass the portfolio checks.
